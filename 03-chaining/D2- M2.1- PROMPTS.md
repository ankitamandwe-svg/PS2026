## Prompt chain: Building Trust with Users 

### Step 1: Expand, build new screens in a strict sequence
```
Build the next phase of this app in a strict sequence:
1. Add a screen "My Profile". Match the layout and spacing same; no changes
2. Add a screen "Payments". Match the data density of the new screen with the rest
3. Navigation: write the logic so - Sign in - My Profile-Find Care - Payments
4. Add another screen that shows the activity - how many booking slots are availble for all providers - its a dashboard screen to track utilization, bookings confirmations, no show and other relevant data 

Build these in order so Find care is the anchor for Payments
```

### Step 2: Behavior, hard-code the states
```
Apply the following logic constraints to the siteflow:
- Use sign in page as start and validate the email id and password, keep skip as option
- Profile information should be saved in the AWS data base

Maintain the same design language throughout and tether all behavior strictly to these rules.
```

### Step 3: Refine, one surgical polish
```
Experiment screen was somehow removed from the build; so added it back with toggle to check the hypothesis

Don't change anything else in the project or touch the underlying logic.
```
